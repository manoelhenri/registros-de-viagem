# Instruções para agentes de código

Este arquivo vale para qualquer agente (Codex, Antigravity, Claude Code e outros). O `CLAUDE.md` só importa este arquivo, então **edite sempre aqui**. Quando uma regra ou a estrutura do projeto mudar, atualize este arquivo no mesmo commit.

## O que é este repositório

Blog pessoal de viagens do Manoel Henrique, "registros de viagem", no ar em **https://viagens.manoelhenrique.com**. Todo o conteúdo é em português do Brasil. O mesmo repositório também publica os jogos em **https://jogos.manoelhenrique.com** e as receitas em **https://receitas.manoelhenrique.com** ("Pães do Manoel"), produtos separados do blog (ver "Jogos ficam separados do blog" e "Receitas ficam separadas do blog", abaixo).

## Domínios (três sites)

O dono decidiu separar as três áreas em subdomínios: **viagens.manoelhenrique.com** (blog), **jogos.manoelhenrique.com** e **receitas.manoelhenrique.com**. O domínio antigo `manoelhenrique.com` (e `www`, `blog.` e `viagem.`) só redireciona: `/jogos/...` e `/receitas/...` para os subdomínios (pelo `_redirects` do blog) e todo o resto para `viagens.` (por uma regra de redirecionamento da zona na Cloudflare, ver `COMO-PUBLICAR.md`).

- **`sites.json`** (raiz, fora do Eleventy) guarda os endereços e a chave `separado`. Hoje está em `true` (virada feita). Com `false`, o build do blog voltaria a publicar `/jogos` e `/receitas` no domínio antigo, como antes, e os sites próprios de jogos e receitas sairiam com `noindex`. A virada trocou para `true`, junto com `url` em `_data/site.json` (`https://viagens.manoelhenrique.com`), `site_url`/`display_url` e o `public_folder` da coleção de receitas (`/assets/img/fotos`) no `admin/config.yml`.
- **Três projetos do Cloudflare Pages, o mesmo repositório:** o projeto atual (`registros-de-viagem`, comando `npm run build`) é o blog e mantém o `pages.dev` do login do painel; `npm run build:jogos` e `npm run build:receitas` geram os outros dois sites em `_site/`, com as páginas na raiz.
- **Redirecionamentos:** cada site gera o próprio `_redirects`. A lista de receitas que mudaram de endereço fica em `static-receitas/redirecionamentos.json` e é usada nos três modos.
- **Jogo instalado:** depois da virada, `/jogos/quem-e-mais/sw.js` no domínio antigo continua respondendo (regra 200 para `/legado/quem-e-mais-sw.js`), com um service worker que apaga a cópia guardada, se desinstala e recarrega a página, que é redirecionada. Nunca troque essa regra por um 301.
- **Painel:** continua em um só lugar (no domínio do blog) e edita os três sites. `functions/api/callback.js` já aceita `viagens.manoelhenrique.com`.
- O que fica guardado no navegador (receitas salvas, configurações do jogo) não passa de um endereço para outro.

## Stack

- **Gerador:** Eleventy 2 (`@11ty/eleventy ^2.0.1`), templates Nunjucks (`.njk`), `markdown-it` com plugins próprios (`lib/video.js`, `lib/callout.js`).
- **Node 20** (`.nvmrc`). Dependências em `package.json`: só `@11ty/eleventy`, `markdown-it` e `gray-matter`. Não adicione framework (React, Tailwind, bundler etc.) sem o dono pedir.
- **Build:** `npm run build` (saída em `_site/`). Servidor local: `npm run serve`.
- **Hospedagem:** Cloudflare Pages ligado à branch `main`. **Todo push na `main` publica o site em cerca de 1 minuto.**
- **Painel de conteúdo:** Decap CMS em `/admin`, para o blog e para as receitas (`admin/index.html` + `admin/config.yml`), versão fixa `decap-cms@3.1.3`, backend `github`. Login OAuth via Cloudflare Pages Functions em `functions/api/auth.js` e `functions/api/callback.js`.
- **Mapa:** Leaflet + tiles do OpenStreetMap (`mapa.njk`). Coordenadas novas são buscadas sozinhas no build via Nominatim (`lib/geocode.js`, `lib/coordsAutomatico.js`, cache em `_data/coordsAutoCache.json`); `_data/coordsMapa.json` guarda só correções manuais e sempre vence o automático.
- **Visual do blog:** tudo em `style.css`, cores em variáveis no `:root` (`--petrol`, `--paper`, `--ink`, `--sage`, `--sand`), fontes Fraunces, Work Sans e IBM Plex Mono.

## Jogos ficam separados do blog

A área `/jogos/` (hoje: o hub em `static-jogos/index.html`, o jogo "Quem é mais?" em `static-jogos/quem-e-mais/`, o quiz de auditório "Valendo!" em `static-jogos/valendo/` (ex-"Noite do Quiz", ver "Valendo! e as salas online", abaixo) e a política de privacidade em `static-jogos/privacidade/`) é um produto à parte, que só divide o domínio e o repositório com o blog. Regras:

1. **Nenhuma ligação entre os dois.** O blog não linka para os jogos (menu, rodapé, home, posts, sitemap, feed) e os jogos não linkam para o blog. Não misture os dois em nenhum template.
2. **Nada do blog dentro dos jogos.** Os jogos são HTML estático autocontido: não usam `base.njk`, `style.css`, `_data/`, filtros do Eleventy nem a identidade visual do blog. Cada jogo tem visual, fontes, ícones, manifest e service worker próprios.
3. **Fora do Eleventy.** `static-jogos/` está no `.eleventyignore`. Antes da virada, `scripts/build-jogos.js` (função `noBlog()`, chamada no evento `eleventy.after` do `.eleventy.js`) copia os jogos para `_site/jogos/`; o site próprio sai de `npm run build:jogos`, que copia os jogos para a raiz de `_site/` trocando o endereço antigo escrito nas páginas e sobe a versão do cache do `sw.js`. Os links internos dos jogos são relativos: mantenha assim, para funcionarem nos dois endereços. Não mova os jogos para dentro dos templates e não remova esse gancho.
4. **Jogo novo** entra numa pasta própria `static-jogos/<nome-do-jogo>/` e ganha um cartão no hub `static-jogos/index.html`. Nunca na raiz do repositório (uma pasta solta na raiz seria processada pelo Eleventy e quebraria a publicação, como já aconteceu).
5. **Service worker:** ao mudar qualquer arquivo de um jogo com PWA, suba a versão do cache no `sw.js` dele (ex.: `quem-e-mais-v5` para `quem-e-mais-v6`) e mantenha a lista de arquivos em dia, senão o celular de quem já instalou continua com a versão antiga.
6. **`_redirects` e `_headers` do blog são gerados por `scripts/build-jogos.js`** (`noBlog()`), e os do site de jogos pelo mesmo script com `--sozinho`; os das receitas, por `scripts/build-receitas.js --sozinho`. Eles sobrescrevem qualquer arquivo com esse nome. O endereço antigo `/quem-e-mais` redireciona (301) para o jogo; não quebre isso.
7. **Arquivos na raiz do domínio** (ex.: `.well-known/assetlinks.json`, para vincular o app Android) vão em `static-root/`, que o mesmo script copia para a raiz de `_site/` do blog e do site de jogos (é no `jogos.manoelhenrique.com` que o app Android vai procurar). A pasta ainda não existe; crie quando precisar e mantenha no `.eleventyignore`.

## Valendo! e as salas online

O Valendo! (quiz de auditório inspirado nos programas de perguntas valendo dinheiro; antes se chamava "Noite do Quiz" e era de Halloween, e `/noite-do-quiz` redireciona com 301 no site de jogos) tem partida online para até 10 celulares, com um servidor próprio em **https://salas.manoelhenrique.com** (pasta `salas/`, fora do Eleventy e no `.eleventyignore`).

1. **Servidor:** um Worker da Cloudflare (`salas/src/index.js`, config em `salas/wrangler.jsonc`) com um Durable Object por sala (SQLite, plano grátis). O código da sala tem 4 consoantes e é o nome do Durable Object. A sala é a única fonte de verdade: sorteia temas e perguntas, marca o tempo com alarmes e calcula os pontos; os celulares só mandam ações por WebSocket (`entrar`, `perfil`, `foto`, `rodadas`, `temas`, `comecar`, `votar`, `ajuda`, `responder`, `proxima`, `denovo`, `saguao`, `sair`, `ping`). Só aceita conexões de origens `*.manoelhenrique.com`, `*.pages.dev` e localhost.
2. **Regras num lugar só:** `static-jogos/valendo/motor.js` (regras puras) e `perguntas.js` (temas e perguntas; a primeira alternativa é a certa) são usados pelo navegador no modo de um celular só e importados pelo servidor. Mudou uma regra ou pergunta, as duas pontas mudam juntas. Durante o voto e a pergunta o servidor só conta QUEM já agiu (`publico()`), nunca o quê.
3. **Publicação:** o Worker `salas-jogos` é publicado pelo Workers Builds da Cloudflare a cada push na `main` (diretório raiz `salas`, comando `npx wrangler deploy`; o Wrangler fica fixo em 4.86.0, a última versão que roda no Node 20 usado pelo build por causa do `.nvmrc` da raiz), e o domínio `salas.manoelhenrique.com` vem da própria config (`custom_domain`). A ligação inicial é feita uma vez no painel da Cloudflare (ver `COMO-PUBLICAR.md`). Sem o servidor no ar, o jogo avisa e o modo de um celular só continua funcionando.
4. **Testar localmente:** `cd salas && npm install && npx wrangler dev --port 8787`; o jogo servido em `localhost` usa `ws://127.0.0.1:8787` sozinho (ou `?servidor=` só em localhost).
5. **Reconexão:** o celular guarda um id (`vl_pid`) no `localStorage` e volta para a mesma sala com os mesmos pontos se cair. Se o anfitrião cair, o próximo conectado assume. Quem entra no meio da partida começa com zero.
6. **Formato:** escada de prêmios por rodada (`ESCADAS` no `motor.js`, para 10, 15 ou 20 rodadas, sempre terminando em R$ 1 milhão); acerto vale o prêmio da rodada e erro vale zero; no empate de dinheiro, ganha quem somou menos tempo de resposta (`ordenar()`/`posicoes()`). Cada jogador tem três ajudas por partida, uma de cada (Cartas, Universitários, Placas): o servidor só registra o uso (`usarAjuda`), e o efeito é sorteado no celular. A resposta tem confirmação ("Tô certo disso!").
7. **Temas:** o anfitrião escolhe os temas no saguão (mínimo de 3; com menos, valem todos). `perguntas.js` tem 31 temas e 620 perguntas (nov/2026), revisadas uma a uma; ao incluir pergunta, confira o fato, mantenha 4 alternativas diferentes com a certa em primeiro e evite fato que muda com o tempo sem data na pergunta.
8. **Fotos:** a foto é feita e filtrada no celular (`foto.js`, canvas, sem biblioteca) e sai redonda, com 192 px e no máximo 30 KB. Online, o servidor só aceita `data:image/jpeg` desse tamanho, guarda na sala (chave `fotos`) e apaga junto com a sala. A política de privacidade (`static-jogos/privacidade/`) descreve isso; mudou o que vai para o servidor, atualize a política.
9. **Som:** `som.js` sintetiza trilha e efeitos com a Web Audio API (nada gravado nem de terceiros). Só começa depois do primeiro toque; o botão de som fica guardado em `vl_mudo`.
10. **Cartaz do campeão:** a tela final monta uma imagem 1080x1350 no canvas e usa o compartilhamento do aparelho (com arquivo, quando o navegador deixa) ou o download.

## Receitas ficam separadas do blog

A área `/receitas/` ("Pães do Manoel": receitas para panificadora, com guia da máquina e os livros em PDF, hoje fora do ar por estarem desatualizados) segue as mesmas regras de separação dos jogos: nenhum link entre ela e o blog (nem menu, rodapé, sitemap, feed ou `robots.txt`), nada do blog dentro dela (sem `base.njk`, `style.css`, filtros do Eleventy nem Google Analytics) e fora do Eleventy. O foco é a experiência online; os PDFs são só um download secundário. Regras próprias:

1. **Dados editáveis pelo painel:** as categorias ficam em `static-receitas/categorias.json` (`categorias`, `livros`) e cada receita é um arquivo `static-receitas/receitas/<slug>.json`, no formato da coleção "Receitas (Pães do Manoel)" do `admin/config.yml`. **O nome do arquivo é o slug.** Campos: `titulo`, `ordem` (posição na home; vazio vai para o fim), `publicado` (data real de publicação, AAAA-MM-DD, vira `datePublished`), `categoria`, `tags` (região e ocasião, lista fechada no painel), `resumo`, `foto` + `fotoAlt` (opcionais), `icone`, `programa`, `casca` (vazio quando o programa não tem cor), `timer`, `nivel`, `rende`, `origem` (`{tipo: oficial|adaptada|autoral, fonte}`), `quantidades` (`oficial`, `calculadas` ou `unica`; os três tamanhos 500/750/1000 g saem daqui, não há campo de colunas), `tamanhoBase` (nas calculadas: o tamanho de onde as outras colunas saíram por proporção), `tabelas` (`[{grupo, itens: [{nome, quantidade, q750, q1000}]}]`, na ordem de colocar na forma; `quantidade` é a de 500 g ou a única), `preparo` (`[{grupo, passos: [texto]}]`), `pronto`, `guardar`, `dica` e, opcionais, `imagens` e `complemento` (`{titulo, intro, passosTitulo, passos, itens: [{nome, ingredientes: [{nome, quantidade}], modo}]}`; hoje usado nos 5 sabores da massa de pizza). `carregar()` no gerador converte para o formato interno. Receita com erro grave (sem título, categoria desconhecida, sem ingrediente ou passo, ou de três tamanhos sem as três quantidades) fica fora do site com `[receitas] ERRO` no log, e as outras publicam; foto inexistente ou acima de 700 KB só gera aviso. Mudou um campo, mude junto o `admin/config.yml`, o `carregar()` e a seção "Editar as receitas" do `GUIA-DO-BLOG.html`. Receita nova ou correção é só editar esses arquivos (pelo painel ou direto); não escreva HTML de receita à mão. **Medidas por extenso:** `1 colher (chá)`, `3 colheres (sopa)`, nunca `cc`/`cs`. Os nomes dos ingredientes ficam em negrito nos passos automaticamente (`realce()` no gerador, a partir dos nomes das `tabelas`); escreva os passos com os mesmos nomes da lista.
2. **Gerador:** `scripts/build-receitas.js` (só módulos do Node, sem dependência) roda de dois jeitos: dentro do build do blog, antes da virada, em `_site/receitas/` (`BASE` `/receitas/`), e sozinho (`npm run build:receitas`), na raiz de `_site/` (`BASE` `/`), com `_redirects`, `_headers` e `robots.txt` próprios. Use sempre `${BASE}` nos caminhos; a foto é guardada como caminho relativo (`assets/...`). Ele cria a home (`index.html`, com busca, filtros, categorias e receitas salvas), uma página por receita em `_site/receitas/<slug>/`, o guia da máquina em `_site/receitas/guia/`, `404.html` e `sitemap.xml` próprios, e copia `static-receitas/assets/` (CSS, JS, fontes, ilustrações, imagens de compartilhamento e PDFs). É chamado num gancho `eleventy.after` separado, **dentro de try/catch**: se as receitas quebrarem, o blog e os jogos publicam normalmente e o erro aparece no log como `[receitas]`. Não junte esse gancho com o dos jogos.
3. **Slug** é o nome do arquivo da receita, normalizado para `a-z`, `0-9` e hífen (acentos saem), e nunca muda depois de publicado (é o endereço indexado pelo Google). O painel cria o arquivo pelo título só na criação e não deixa apagar receita (`delete: false`): para tirar uma do ar, apague o arquivo e crie o 301 (regra 4).
4. **Fontes e tamanhos (catálogo de 100, nov/2026):** as receitas seguem o Manual de Instruções e o Livro de Receitas da Gallant e, como biblioteca complementar, o manual Britânia Multi Pane. As 12 receitas do livro da Gallant usam as quantidades oficiais nos três tamanhos (o livro chama de 700 g o tamanho de 750 g do painel). Três tamanhos só nos programas 1 a 7, os únicos com seletor de peso; nos outros (Massa, Bolo, Geleia, Sovar, Misturar e Assar) a receita tem quantidade única, e o programa Massa aceita no máximo 1 kg de ingredientes. O aviso de adição só existe nos programas 1 a 7: com o programa Massa, frutas e passas entram à mão na modelagem. A página mostra a origem e se as quantidades são oficiais ou calculadas; não apague essas marcas. Receita que sai do catálogo ou muda de endereço ganha redirecionamento 301 em `scripts/build-jogos.js` (para a substituta, se for o mesmo prato, ou para `/receitas/`). Líquidos em temperatura ambiente (20 °C a 25 °C) e cerca de 20 minutos antes de fatiar, como no manual.
5. **Quantidades:** as receitas de pão foram conferidas por porcentagem de padeiro (hidratação, sal cerca de 2% e fermento cerca de 1% da farinha, iguais nos três tamanhos). Ao mudar uma quantidade, mantenha a proporção entre as colunas de 500, 750 e 1000 g; quando o ovo não acompanha a escala (1, 1, 2), a coluna de 750 g leva cerca de 20 ml a mais de líquido.
6. **SEO:** cada página tem `description`, `canonical`, Open Graph e JSON-LD (`Recipe` com ingredientes do tamanho de 750 g e passos em `HowToSection`; `BreadcrumbList`; `ItemList` na home). Sem tempos de preparo no JSON-LD, porque a duração dos ciclos da máquina não é publicada; não invente. Imagens de compartilhamento por categoria em `assets/img/<categoria>-<1x1|4x3|16x9>.jpg`. O sitemap das receitas (`receitas.manoelhenrique.com/sitemap.xml`) fica no `robots.txt` do próprio site de receitas e no Google Search Console; nunca no sitemap ou no `robots.txt` do blog.
7. **Imagens das receitas** hoje são ilustrações. Foto real entra pelo campo `foto` do painel, que grava o arquivo em `static-receitas/assets/img/fotos/` e o caminho `/receitas/assets/img/fotos/<arquivo>`; com ela, a foto substitui a ilustração na página, no cartão, no JSON-LD e no Open Graph. O campo antigo `imagens` (nomes de arquivo em `assets/img/`, nas proporções 1:1, 4:3 e 16:9) continua aceito só para JSON-LD e Open Graph. Não há redimensionamento no build: peça fotos de até uns 500 KB.
8. **Domínio:** dentro do build do blog, o gerador lê a URL de `_data/site.json`; sozinho, lê `receitas` em `sites.json`. Não escreva o domínio fixo.
9. **Interface:** a página só liga e desliga elementos que já vêm prontos no HTML (busca, filtros, tamanho do pão, marcar ingredientes e passos, receitas salvas e modo cozinha, tudo guardado no `localStorage` do navegador). Botão sem efeito não pode ficar na tela: copiar e compartilhar tentam a área de transferência, depois `execCommand` e, se o navegador negar (navegadores de dentro do Instagram e outros apps), mostram o texto pronto numa caixa (`.copia-manual`) para copiar com o dedo; "Imprimir" some nesses navegadores de app; "Desmarcar tudo" só aparece com algo marcado; o modo cozinha só diz "tela acesa" quando o Wake Lock foi concedido. O CSS e o JS entram com `?v=<hash do conteúdo>` (calculado no gerador) para o celular não ficar com a versão antiga depois de publicar. Texto de dado sempre passa por `esc()` no gerador. Sem JavaScript, a página continua legível (as três quantidades aparecem juntas). Teste no celular: nenhuma página pode ter rolagem horizontal em 375 px.
10. **Mobile primeiro (quase todo acesso é pelo celular):** abaixo de 600 px a lista usa cartões compactos (miniatura à esquerda) e a receita tem a barra fixa "Ingredientes / Modo de preparo" (abaixo de 960 px). Toda página tem o botão Início no topo (só o ícone de casa até 400 px) e o botão flutuante "Topo" (`[data-topo]`), que aparece depois de rolar cerca de uma tela e meia; o rodapé tem espaço extra embaixo para ele não cobrir os links. O cabeçalho precisa caber em 320 px. O filtro esconde cartões com o atributo `hidden`, que precisa vencer no CSS (`[hidden]{display:none!important}`). Atalhos (links com `data-f-*`: abertura, categorias, "Ver as 9", etiquetas) sempre limpam os outros filtros antes de aplicar o seu; só os controles da própria lista se combinam. Valor de filtro desconhecido no endereço é ignorado. O `html` já tem `scroll-padding-top`; não some `scroll-margin` por cima. Teste filtros num celular simulado (Playwright, iPhone SE e iPhone 13) conferindo que o número de cartões visíveis bate com o contador. Filtros só com dado real do cadastro (hoje: categoria, etiquetas, timer, `nivel` Fácil, origem oficial Gallant, salvas); com 2 ou mais palavras sem resultado completo, a busca mostra as receitas com parte delas ("o que tenho em casa").
11. **Confiabilidade:** nada de dado inventado (tempo de preparo, custo, calorias, avaliações). O guia e as receitas são da Gallant GPA1E19A; diga o modelo quando a informação for específica dele. Receita com a etiqueta "Sem glúten" mostra o alerta de rótulo e contaminação cruzada (feito no gerador); "sem lactose" ou "vegetariano" só depois de revisão receita a receita.
12. **Acessibilidade e desempenho:** a cor de cada categoria é escurecida no gerador (`tinta()`) até 4,5:1 sobre o branco e sobre o fundo claro dela; não use a cor crua como texto. A Fraunces é uma versão reduzida (pesos 600 a 900, tamanho óptico fixo, eixo SOFT mantido); não troque pelo arquivo completo. Meta: Lighthouse mobile com acessibilidade 100.

## Regras de manutenção do blog

1. **Imagens:** nunca invente link. Use Wikimedia Commons no formato `https://commons.wikimedia.org/wiki/Special:FilePath/<Arquivo>?width=1280` (capas) ou `?width=640` (destinos e parques), confirme que o arquivo existe e mostra o lugar certo, prefira fotos horizontais. Nunca escreva à mão links `upload.wikimedia.org/.../thumb/...`.
2. **Crédito obrigatório** em foto de terceiros: `capaCredito` (autor · licença · Wikimedia Commons) e `capaFonte` (página do arquivo).
3. **Só um post com `destaque: true`.** O build dá erro se houver mais de um.
4. **Nunca dê a um arquivo de `_data/` o nome de um campo do front matter** (`coordenadas`, `cidades`, `data`, `title`, `resumo`, `capa`...). O dado global sobrescreve o campo em todos os posts sem avisar.
5. **Painel (Decap):** coleção de arquivo nunca aponta para JSON cujo topo seja uma lista; envolva num objeto (`{"chave": [...]}`) e crie um `_data/<nome>.js` que desembrulha, como `destinos.js`/`parques.js`. **Não apague `_data/destinos.js` nem `_data/parques.js`.**
6. **Versão do Decap é fixa** (`decap-cms@3.1.3`, sem `^` ou `~`). Ao subir de propósito, teste as 8 coleções antes (6 do blog e 2 das receitas). As coleções das receitas só apontam para `static-receitas/`; não misture campos do blog nelas.
7. **Segurança do login:** não remova as checagens do `callback.js` (confere `e.origin`, `postMessage` restrito à própria origem, nunca `"*"`) nem os atributos `Secure` + `HttpOnly` + `SameSite=Lax` do cookie `oauth_state`. O login pede só `public_repo,read:user` (o repositório é público); não volte para `repo`. O `callback.js` apaga o cookie `oauth_state` em toda resposta e manda `Cache-Control: no-store`.
8. **URL pública só em `_data/site.json` → `url`.** Use `{{ site.url }}`; não escreva o domínio fixo em template, CSS ou JS do blog. Exceção proposital: `admin/config.yml` → `base_url` aponta para `registros-de-viagem.pages.dev` (login do painel). Outra exceção: `functions/api/callback.js` lista `manoelhenrique.com` (com e sem www) nas origens que podem receber o token, porque o painel é aberto no domínio próprio e o login volta pelo `pages.dev`; mudou o domínio, atualize essa lista.
9. **Matching post ↔ destino/parque** é por igualdade exata normalizada (sem acento, minúsculo), nunca por "contém". Não troque por busca de substring.
10. **Campos opcionais da ficha de viagem** (perfil, transporte, hospedagem etc.) nunca viram obrigatórios no painel.
11. **Filtros de listagem** reusam `.filter-bar`/`.filter-chip`/`.filter-search`/`.filter-select` e o estado vazio com `aria-live="polite"` + botão "Limpar filtros".
12. **Capas clicáveis** (vídeo e mapa) usam os atributos genéricos `data-embed-*` lidos por um único handler em `base.njk`. Reuse esse padrão.
13. **Vídeo é sempre link externo** (YouTube, Vimeo, Instagram), nunca arquivo no repositório. Só vira player se o link estiver sozinho na linha.
14. **Convenção de `coordenadas` no front matter:** nome do lugar em maiúsculas (`"SALVADOR"`) ou paradas com seta (`"GRAMADO → CANELA"`), sem números.
15. **`GUIA-DO-BLOG.html` acompanha o painel.** Mudou um campo ou fluxo do painel ou do blog, atualize a seção do guia no mesmo commit.
16. **Arquivo novo na raiz** que não deve virar página (`.md`, `.html` de documentação, pastas estáticas) precisa entrar no `.eleventyignore`.
17. **Não suba ZIP** nem arquivos gerados (`_site/`, `node_modules/`).
18. **SEO por página:** toda página tem `description` própria (front matter ou `eleventyComputed`); o `base.njk` só cai no texto genérico quando falta. Números (destinos, países, parques, posts) vêm de `estatisticas`, nunca digitados. `seoTitle` no front matter substitui o título padrão "<title> — registros de viagem" (usado na Home). Em `eleventyComputed` com texto vindo de dado, use `| safe` para não escapar duas vezes (o `base.njk` já escapa).
19. **Datas de post para o Google** (`datePublished`/`dateModified` no JSON-LD e `<lastmod>` no sitemap) vêm do histórico do Git (`lib/datasGit.js`), não do campo `data`, que é a data da viagem. Se o build não tiver histórico, essas datas ficam de fora; nunca troque por uma data inventada.
20. **HTML montado no navegador** (ex.: popup do mapa) usa `document.createElement` + `textContent`, nunca texto concatenado em HTML. Dados do painel podem ter `&`, `<` e aspas.
21. **Google Analytics** (`G-SZSXHX6PQE`) fica no `<head>` do `base.njk`, só no blog. Não coloque nos jogos (produto separado) nem no `/admin`.

## Textos e preferências do dono

- **Não use travessão (—)** em texto que aparece para o leitor (posts, páginas, painel, guia, jogos). Prefira vírgula, dois-pontos, parênteses ou frase nova.
- **Nunca publique texto autoral em nome do dono sem aprovação.** Texto em primeira pessoa (Sobre, home, posts) vai primeiro como rascunho para ele revisar. Use só fatos que ele já publicou ou confirmou; não invente detalhes da vida ou das viagens.
- A página Sobre não fala de milhas nem de programas de benefício.
- Conteúdo do dia a dia (posts, fotos, destinos) é feito pelo painel `/admin`. Mudança de código é feita pelo agente: o dono não tem Git nem Node no computador (Windows) e não faz passos manuais no GitHub.

## Como trabalhar e publicar

1. Antes de publicar, rode `npm install` e `npm run build` e confira que termina sem erro e sem aviso novo das validações (`validarBuild()` no topo do `.eleventy.js`).
2. Para mudança visual, teste as páginas afetadas em desktop e mobile (sem rolagem horizontal, sem erro de console). Post de teste temporário pode ser usado, mas nunca commitado.
3. Commits pequenos e coesos, mensagem em português descrevendo a mudança.
4. Lembre que push na `main` publica na hora. Mudança grande ou arriscada pode ir numa branch com PR, que o Cloudflare Pages publica como prévia.
5. Depois de publicar, confira o site no navegador. `raw.githubusercontent.com` tem cache de alguns minutos; para ver o estado real use a página `github.com/.../blob/main/<arquivo>`.

### Ambientes com rede restrita

Alguns sandboxes bloqueiam `unpkg.com` (Decap e Leaflet), `nominatim.openstreetmap.org` e o próprio domínio do site. O build continua funcionando: a geocodificação falha só com um aviso `[geocode]` no terminal. Para testar uma página que depende de CDN bloqueado, baixe o pacote com `npm pack <pacote>@<versão>`, aponte a página para a cópia local só durante o teste e **reverta antes de commitar**. Para testar o painel sem OAuth, use `npx decap-server` com `local_backend: true` temporário no `config.yml`, nunca commitado.
